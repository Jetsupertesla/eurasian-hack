# One photo to a 3D scene you can fly through and extend

One photo of a room becomes a Gaussian-splat scene in the browser. Fly the camera anywhere, press
**Generate**, and an image model repaints what the camera sees: it repairs what looks wrong and continues
into what was never photographed. The repainted view is turned into splats and joins the scene.

Two models do the work. An image-editing model (called through [fal](https://fal.ai)) invents the pixels.
[Apple SHARP](https://github.com/apple/ml-sharp) turns one image into Gaussian splats on the local machine,
in about 20 seconds per image on an M2.

## Pipeline

### 1. Generate from the camera

This is the main loop. Each press of Generate runs these steps in `world/serve.py`:

1. **Capture.** The viewer sends the framed view and the camera's position and direction.
2. **Repaint.** The image model (`minimax/h3-image/edit`) redraws the capture as a clean photo taken from the
   same spot. It keeps what is there, repairs smeared or torn areas and fills the black, uncaptured areas.
   An optional text prompt asks for a specific change.
3. **Lift to 3D.** SHARP turns the repainted image into splats.
4. **Fit.** The new splats get one depth scale, chosen so their surfaces sit where the scene's existing
   surfaces are in that frame, and are moved to the camera's pose.
5. **Replace.** Splats the scene already had inside the frame are cut out and the new ones take their place.
   Every step is saved as a snapshot, so Undo and Redo move between them. No geometry file is ever deleted.

One generation takes about 40 seconds and costs about $0.03.

### 2. Starting scene from one photo

`world/make.py` builds the scene the camera starts in:

1. **Guide** (`guide.py`). The photo is placed in the middle of a black 360° canvas, assuming it spans 75°
   horizontally.
2. **Panorama.** The image model (`google/nano-banana-2.1/edit`) paints the rest of the canvas, giving a 360°
   panorama of the room.
3. **Seam** (`seam.py`). The tone is evened out where the panorama's two ends meet.
4. **Build** (`build.py`). The panorama is cut into 12 overlapping views (6 level, 3 looking down, 3 looking
   up). SHARP runs on each. Each view gets one depth scale, fitted where neighbours overlap, and is trimmed to
   the directions it covers best. The result is `view_XX.ply` files and a `world.json`.

A scene takes about 4 minutes on an M2 and one image call (about $0.14).

By default the viewer opens with only the front view, so the rest is generated by hand with step 1.
Add `?mode=360` to the URL to see the full prebuilt panorama scene instead.

## Run it

You need Node, a fal API key, and Apple SHARP installed in a Python environment with its weights downloaded
(about 2.8 GB; running `sharp predict` once fetches them). The server uses `.sharp/venv/bin/python` if it
exists; otherwise set `SHARP_PYTHON`.

    npm run setup:fal     # paste your fal key; it is saved to .env, which is git-ignored
    npm start             # or double-click Start.command, then open http://localhost:3095/world/

The splat files are about 300 MB per scene and are not in git. Rebuild one from its panorama, which is in
git, with `python world/build.py room3` (no API key needed), or copy `world/worlds` from a machine that has
them.

To make a scene from your own photo:

    python world/make.py originals/room3.jpg myroom
    python world/make.py originals/room3.jpg jungle "abandoned for decades and reclaimed by nature"

### Controls

| Input | Action |
| --- | --- |
| Drag | Look around |
| W A S D, Q / E, Shift | Move, down / up, faster |
| Scroll | Zoom |
| G | Generate the framed view |
| [ and ], or Cmd/Ctrl+Z | Undo and redo generations |
| B | Image library: pick or upload the starting photo |
| R | Reset the camera |
| 1 to 9 | Switch scene |

## Repository layout

| Path | What it is |
| --- | --- |
| `world/index.html` | The viewer (three.js and Spark, vendored in `lib/`) |
| `world/serve.py` | Local server: serves the viewer and runs generate, history and the image library |
| `world/make.py`, `guide.py`, `seam.py`, `build.py`, `geo.py` | Photo to starting scene |
| `world/history.py`, `library.py`, `config.py` | Snapshots for undo and redo, the photo library, key loading |
| `world/worlds/<name>/` | One scene: photo, panorama, `world.json`; splat files are git-ignored |
| `viewer.html`, `prep.mjs`, `edit.mjs`, `score.mjs` | An earlier before/after restyle demo; see `DEMO_README.md` |

More detail on the scene tools is in `world/README.md`.

## Limits

- Everything outside the photo is invented by an image model, not measured.
- The scene is most accurate near where the photo was taken. Further away, surfaces stretch until that view
  is regenerated.
- A generated view is aligned to its surroundings by a single depth scale, so joins with neighbouring areas
  can show.
- SHARP's weights are licensed for research and non-commercial use only.
